버전: 1.3.0

관리 대상: Blair의 파머스 데스크 업무·개인 업무표·출력·교재·신규생 준비

## 1. 이 문서의 사용법
파머스 업무를 시작할 때 이 문서와 관련 Google Sheets의 최신 원본을 먼저 읽는다. 채팅 기억이나 지난달 표만으로 수행하지 않는다.
사용자가 새로 확정한 변경 → 관련 원본의 최신 확정 내용 → 이 문서의 원칙 → 과거 이력 순으로 적용한다.
서로 충돌하면 확인된 변경만 반영하고, 불확실한 단계·자료·인원·시각·장소·완료를 임의 결정하지 않는다.
사용자가 운영 방식을 바꾸면 이 문서의 해당 절을 수정하고 버전·날짜·변경 이력을 갱신한다. 모순된 규칙을 끝에 계속 쌓지 않는다.
이 저장소는 공개다. 학생명·학교·학년·연락처·개별 청구·결제·개인 시트 주소·접근키는 저장하지 않는다. 실제 명단과 개인별 예외는 비공개 업무표에서 관리한다.
이 문서는 업무 원칙이다. 명단·부수·완료 상태를 고정한 데이터베이스가 아니다. 모든 예시는 계산 설명용이다.

## 3. 업무표 원본과 식별
개인 업무표를 기준으로 아래 탭을 연결한다. 실제 이름·sheetId·범위는 매 실행 시 metadata로 확인한다.
- 업무 홈: 오늘 탭 링크.
- 일간 체크리스트: 근무일·픽업 시간·최신 하원문자 메모. 숨김이어도 읽는다.
- [CUR] Monthly Tasks: 업무 월·업무 구분·할 일·마감일·완료·완료일·지원 내용·메모·표시 시작일(A:I, 헤더4행).
- [CUR] Monthly Printing [준비 월 숫자]: 사용 월과 준비 월을 구분한 정기 출력.
- 신규생 이름표 검수: 첫 등원월별 명단·이름표 상태.
- 재출력 기록: 학생·자료·부수·사유·출력/비치 이력.
- [CUR] 교재 주문·청구 [준비 월 숫자]: 실제 사용월을 상단에서 확인.
- 예외처리: 검색 가능한 예외 기록. 완료 건은 처리완료 표시 후 아래에 배치.
- [ARCH] Daily Tasks: 과거 실제 체크 업무의 연속 이력.
- [ARCH] Desk 기록: DESK 원문 보존.
- [ARCH] 셔틀: 모든 셔틀 지원·승하차·변경·완료 상세를 날짜·호차별로 누적.
기본 식별자는 월간 '업무 월 + 정규화한 업무명', 이력 '날짜 + 구분 + 시간 + 정규화한 업무명'이다.
표시용 줄바꿈·연속 공백은 비교 시 공백 하나로 정규화한다. 학생명이 비슷하다는 이유로 같은 사람으로 합치지 않는다.

## 3A. 커리큘럼과 진급 경계
2026-11-26 사용자 확정:
**Interbridge3 → Bridge1-1 → Bridge1-2 → Bridge2-1 → Bridge2-2 → Bridge3-1 → Bridge3-2 → InterStella**
Bridge는 위6단계를 총6개월 학습한 뒤 InterStella로 진급한다.
단계 숫자를 기계적으로 늘려 Interbridge3 다음을 Interbridge4로 만들지 않는다. 과정 경계에서는 실제 진급 경로와 새 과정의 자료 규칙을 적용한다.
과정(학습 단계)과 분반/요일 접미사(A/B/C/T/AT/CF)를 분리해 관리한다. 접미사가 곧 다음 단계라는 뜻은 아니다.
아직 미확정인 전체 Space/Pre/Silver/InterStella의 마지막 단계·전환 조건·자료 규칙은 사용자 확인 후 이 절에 갱신한다.
월간 정기 프린트는 Space(phonics)·PreStella·SilverStella·Interbridge까지만 수행한다. 크게 초등 단계이며, Bridge부터는 초등 프리미엄으로 분류한다.
상위 과정은 Bridge → InterStella → GoldStella → The Class, Suno, Aristos 등이 있다. Bridge 이후의 세부 분기·순서는 별도 확정 전 직선 진급표로 단정하지 않는다.
Bridge 이상은 문법·단어 외부교재를 사용하므로 Blair의 월간 정기 프린트 대상에서 제외한다. 해당 과정 신규생에게 프린트 자료 확인 투두도 자동 생성하지 않는다. 별도 요청된 일회성 복사 업무는 예외다.

## 4. 프린트 핵심 원리
### 수행 대상 경계
**Space(phonics), PreStella, SilverStella, Interbridge만 월간 정기 프린트 대상이다.**
Bridge·InterStella·GoldStella·The Class·Suno·Aristos 등은 문법·단어 외부교재 사용으로 월간 프린트 대상에서 제외한다.
Reading Booster 등 위4과정에 포함되지 않는 반에도 정기 프린트 투두를 자동 만들지 않는다. 별도 사용자 요청이 있을 때 해당 건만 처리한다.
신규생이 생겨도 대상 과정 여부를 먼저 판정한 뒤 자료·부수를 계산한다.
### 준비 월과 사용 월
예: 11월에 하는 월간 프린트는 12월 사용분이다. 폴더·탭·기록에 준비 월과 사용 월을 분리한다.
정기 출력의 기준 반은 이전 달에 실제 학습한 단계일 수 있다. 열 제목만 보고 현재/다음 단계로 단정하지 않고, 확정 진도표·반명변경표·자료명을 대조한다.

### 자료 단계 계산
| 과정 | Monthly Test / 평가 | 다음 사용월 Voca |
| --- | --- | --- |
| Space | 기준 단계 그대로 | 기준 단계 +1 음가 Voca 테스트 |
| PreStella | 기준 단계 그대로 | 기준 단계 +1 Voca |
| SilverStella | 기준 단계 그대로 | 기준 단계 +1 Voca |
| InterBridge | 해당 기준 단계 Final, 웹사이트 자료 | Interbridge 안에서의 다음 학습 단계 Voca; Bridge 진급 시 다음 과정 보카 프린트 제외 |
예: 기준 Space3AT → Space3 Monthly Test + Space4 음가 Voca 테스트.
예: 기준 PreA5 → PreA5 Monthly Test + 다음 사용월 PreA6 Voca.
예: 기준 SilverA3 → SilverA3 Monthly Test + 다음 사용월 SilverA4 Voca.
다음 사용월의 반·자료가 이미 확정된 경우 단계 +1을 다시 적용하지 않는다.
예: 다음 사용월 입반 반명이 PreA6A로 확정된 신규생에게는 해당 사용월 PreA6 Voca를 대조한다. 이를 PreA7로 다시 올리지 않는다.
단계 +1과 인원/부수 +1은 서로 다른 계산이다.
Space만 음가를 같은 단계로 두는 과거 예외 수식은 폐기한다.
큰 단계 진급 시 성취도 평가를 확인한다. Interbridge Final·진급 반 성취도 평가는 같은 준비 주차의 하위 업무로 묶는다.
Bridge·Reading Booster·Aristos 등 대상 외 과정에는 정기 프린트나 불필요한 자료 확인 투두를 생성하지 않는다.
시판 Voca 교재 구매 여부와 별도 프린트 유무는 별개의 확인 사항이다.

### 정기 출력 부수
1. 최신 확정 반 명단·현원·사용 자료를 읽는다.
2. 신규 등록·전반·퇴원 변동을 학생별로 반영한다.
3. 실제 필요 부수에서 기존 출력에 포함된 수량을 대조한다.
4. 부족분만 추가 출력한다.
5. 출력 완료와 비치 완료를 각각 확인한다.
신규 등록 1명에 대해 현원 +1과 실제 사용하는 각 자료 필요 부수 +1을 함께 관리한다. 같은 학생 변경을 중복 반영하지 않는다.
사용자가 정한 여유분이 있는 경우 그 수량을 별도로 기록한다. 자료 단계 +1을 여유1부라는 의미로 사용하지 않는다.
전반 전 반의 감원은 최신 확정 명단으로 확인한 경우에만 반영한다.

## 5. 신규생 발생 시 추가 준비 자동 산출 (필수)
사용자가 '신규생이 들어왔으니 업무를 로드해줘'라고 하면 AI가 필요한 자료를 계산해서 결과를 투두로 만든다.
사용자가 자료 종류·단계·부수를 다시 판단하게 만드는 '첫 달 Voca·워크시트 및 시험 필요분 확인·추가 준비' 같은 포괄 문구를 최종 투두로 쓰지 않는다.

### 시험 월과 학습 월을 구분한다
월초에 보는 Monthly Test는 직전 세션에서 학습한 범위를 확인하는 시험이다.
다음 세션 첫 등원 신규생은 직전 세션 학습을 하지 않았으므로 이 시험은 기본적으로 필요 없다.
반면 직전 달에 미리 출력해 둔 다음 세션용 학습 Voca는 신규생도 첫 수업부터 쓰므로 반드시 배정한다.
예: 12월 첫 등원 신규생은 11월 학습분 Monthly Test는 제외하고, 11월에 준비한 12월 사용 Voca는 준비한다.
'첫 달 시험 생략'을 이유로 첫 달 학습 Voca까지 제외하지 않는다.
담당교사가 별도 시험 응시를 확정한 경우에만 해당 시험지를 추가한다.

### 자동 산출 순서
1. 신규생의 첫 등원일·첫 사용월·확정 입반 반·학습 단계를 읽고, Space/Pre/Silver/Interbridge 대상 여부를 먼저 판정한다. 대상 밖이면 월간 프린트 추가0부·수행 불필요로 관리한다.
2. 해당 사용월의 자료 매핑을 기존 월간 프린트·확정 진도표·반명변경표·등록된 담당 예외에서 찾는다.
3. 기준이 이전 달 단계이면 Voca 단계 +1을 한 번 적용한다. 이미 다음 사용월 단계로 확정됐다면 다시 +1 하지 않는다.
4. 첫 달 이전 세션 Monthly Test 필요량은0부, 첫 사용월 Voca 필요량은 학생당1부로 계산한다. 사용하는 별도 워크시트가 확정돼 있으면 해당 자료도 각각 계산한다.
5. 학생별로 기존 정기 출력에 포함됐는지 대조한다. 포함이 확인되면 추가0부·비치 확인, 미포함이 확인되면 추가1부 출력·비치로 정한다.
6. 같은 자료는 인원별 부수를 합산하고 학생별 배정 내역도 유지한다. 단계 +1과 부수 +1을 섞지 않는다.
7. 학생·입반 반·정확한 자료명·총 필요량·기존 포함량·실제 추가량·담당·근거를 기록한다.
8. 수행 가능한 구체적인 체크업무를 로드한다. 제작/출력·비치·불필요·확인대기를 구분한다.
9. 파일·반 배정 등 정말 원본에 없는 부분만 '누구에게 어떤 파일/배정을 확인할지' 지정해 별도 확인업무로 남긴다. 확인 하나가 다른 학생의 확정된 출력업무를 막지 않도록 한다.
10. 새로 확인된 반→자료·담당 매핑은 비공개 업무표에 재사용 가능한 규칙으로 저장한다. 다음 학생 때 같은 질문을 반복하지 않고 변경사항만 재확인한다.

### 허용되는 투두 형태
- 'PreA6A 신규생 2명 · 12월 PreA6 Voca 각1부 출력·비치' + 대상 학생명.
- 'SilverA4C 신규생 · 12월 SilverA4 Voca1부 출력·비치'.
- 정기 출력 포함 학생: '12월 SilverA4 Voca 기출력1부 학생 몫 배정·비치'.
- 대상4과정 안의 자료 미확정 반만 '담임에게 해당 반의 인쇄용 파일명 확인' + 정확히 비어 있는 정보를 적는다. Bridge 이상 등 제외 과정에는 이 확인 업무도 만들지 않는다.
- 센터 출력 제외 확정: '센터 담당 · 데스크 추가0부'. 불필요한 출력 투두를 만들지 않는다.
신규생이 교재를 구매한다는 사실과 학습 자료 매핑은 구분하되, 현재 확정된 월간 프린트 범위는 위4과정으로 제한한다. Bridge 이상과 RB에 Pre/Silver의 +1 자료를 지어내 적용하지 않는다.

### 현재 재사용 가능한 사용월 매핑
| 확정된 12월 입반 단계 | 12월 학습 자료 | 첫 등원생의 11월 범위 Monthly Test |
| --- | --- | --- |
| PreA6A / PreA6B | PreA6 Voca |0부 |

## 7. 교재 주문·청구·안내
각 사용월의 확정 진도표·반 명단으로 새 체크리스트를 만든다. 이전 사용월 체크값·기록은 보존한다.
RD/LS는 한 묶음, Syntax/문법은 별도 항목이다. 내부 RD/LS·Syntax도 Blair의 청구·안내 대상이다.
공용 DESK 최종 Book Order는 사용자 복붙용 A:H 폼을 제공한다. 개인 메모는 공용 복사에서 제외한다.
외부 서점 주문용은 정확한 교재명으로 합산하되 실제 청구 인원·주문 수량·여유분을 구분한다.
등록 이전 보유, 개별 구매, 무료/청구 면제, 퇴원, 기결제, 재사용, 단계 변경 등은 교재별·학생별로 관리한다.
판매기록이 있다는 사실만으로 새 주문·재청구 필요를 단정하지 않는다. 실제 같은 교재의 청구·결제·보유와 사용자/원장 방침을 확인한다.
확정 방침: 이번 보카와 같은 교재의 기존 청구·결제 내역이 확인되면 기존 교재 재사용, 재청구 제외. 판매기록만 보이면 결제까지 확인한다.
문법·독해 등 다른 교재에 이 보카 재사용 결정을 자동 적용하지 않는다.
기결제 교재 정정은 가격·기존 결제 처리 방침을 확인한 뒤 기록한다. 안내문자와 청구 취소·재청구는 별개 완료 상태다.
원비 면제와 교재비 면제를 혼동하지 않고 개별 확정 범위대로 처리한다.

## 8. 일간 투두 생성·이월
한국 시간 매일11시 실행. 해당 날짜 원본 행으로 근무 여부를 판정한다. 휴무·연차 명시는 우선 적용한다.
오늘 행이 없으면 '일간 업무 없음'으로 표시하고 출근·일간 정기업무를 추정하지 않는다.
기존 오늘 탭이 있으면 체크·메모·실제 시각을 보존하고 누락 항목만 보충한다.
먼저 직전 근무일 탭(숨김 포함)의 월간 완료를 원본에 반영한다. 같은 업무 월·업무명이 확실한 건만 반영한다.
월간 원본 H메모에 '시작일 확정', I날짜가 오늘 이하인 미완료 업무만 일간 상단에 올린다.
시작일 미정은 하단 현황에 표시한다. 완료·수행 불필요·예외처리·월간 목록 전용 이벤트는 상단 투두에서 제외한다.
직전 근무일의 미완료 월간 업무는 다음 근무일에 이월한다. 동일 항목은 한 행으로 유지하고 E메모에 마지막 미완료 근무일 'M/D 미완료 이월'을 덧붙인다.
사용자가 지정한 진행일·보류 해제일이 있으면 그날을 우선한다. 휴무일에는 이월 체크업무를 올리지 않는다.
업무 월이 끝났으면 원본에 활성 이월로 명시된 것만 계속 관리한다. 이월 때문에 원래 시작일·마감일을 바꾸지 않는다.
부분 완료는 전체 완료와 구분한다. 오늘 대상 일부만 완료했으면 일간 제목·메모에 해당 범위를 명시하고 월간 전체를 완료 처리하지 않는다.
실제 완료 날짜는 확인된 날짜로 기록한다. 실제 수행 시각이 없는 경우 실행 시간을 대신 넣지 않는다.

## 9. 일간 레이아웃·간결한 작성
1행 날짜 제목, 2행 안내, 3행 헤더, 4행부터 업무, 3행까지 고정. 눈금선 숨김.
열: A구분 / B시간 / C할 일 / D완료 / E기타 / F실제 수행 일시.
폭 약105/95/405/85/520/170px. F는 yyyy-mm-dd hh:mm 고정 입력, 기존값 보존.
제목 짙은 남색·흰 글자·높이52px, 헤더 옅은 파랑. C/E는 의미 단위 실제 줄바꿈과 WRAP, 세로 가운데 정렬.
일반 행 최소36px, 여러 줄은 줄당21px+여유17px 정도. 실제 텍스트가 잘리지 않도록 조정한다.
실제 안내가 있는 E셀·상단 참고사항은 회색 RGB(.949,.957,.965). 빈 기타칸은 비워둔다.
당일 마감·급한 확인·처리 보류만 A/C에 옅은 빨강을 쓴다.
메모는 결론·현재 상태·다음 조치를 첫1~3줄에 쓴다. 긴 원문·출처·과거 경위는 셀메모/원문 아카이브로 옮겨 보존한다.
'사용자 확인', '추정하지 않음', '업무가 아님' 등 불필요한 반복을 줄인다. 금액·학생 예외·기한·수신자·필수 조건은 생략하지 않는다.
D는 실제 체크할 업무에만 BOOLEAN 체크박스. 월간 현황·안내·링크에는 BOOLEAN을 넣지 않는다.
진행률과 막대는 마지막 체크 행 바로 아래 A:D 병합에 둔다. 상단에는 두지 않는다.
진행률 수식:
```
=IF(COUNTIF(D4:D,TRUE)+COUNTIF(D4:D,FALSE)=0,"오늘 체크할 업무 없음","오늘 진행률  "&TEXT(COUNTIF(D4:D,TRUE)/(COUNTIF(D4:D,TRUE)+COUNTIF(D4:D,FALSE)),"0%")&"  ·  "&COUNTIF(D4:D,TRUE)&"/"&(COUNTIF(D4:D,TRUE)+COUNTIF(D4:D,FALSE))&"개 완료")
```
진행 막대 수식:
```
=IF(COUNTIF(D4:D,TRUE)+COUNTIF(D4:D,FALSE)=0,"",SPARKLINE(COUNTIF(D4:D,TRUE),{"charttype","bar";"max",COUNTIF(D4:D,TRUE)+COUNTIF(D4:D,FALSE);"color1","#248272"}))
```
한 행 간격 아래 노랑 제목 '월간 정기업무 리마인드 · 월간 진행 현황', 옅은 노랑 현황. 업무 월·업무·현재 상태·다음 일정을 짧게 표시한다.
새 날짜 탭은 업무 홈 다음 인덱스1. 업무 홈 D4에는 날짜 문자열, E4에는 오늘 sheetId 문자열을 함께 기록한다. B4 링크 수식은 수정하지 않는다.

## 10. 완료 동기화·이력

실제 BOOLEAN 체크박스가 있는 행만 값으로 이관한다. 제목·안내·진행률·월간 현황은 제외한다.
C셀메모·보이는 E안내·기존 사용자 기타 메모와 보존된 상세메모를 합쳐 이력메모에 기록한다. F실제 수행 시각은 이력G에 복사한다.
기존 연속 데이터의 마지막 행 바로 아래 추가한다. 오른쪽 별도 요약표가 있더라도 A:G의 추가 위치와 혼동하지 않는다.
동일 날짜·구분·시간·정규화업무의 중복을 제외하고 누락분만 보충한다.
모든 행이 저장됐는지 재조회한 뒤에만 지난 탭을 숨긴다. 삭제하지 않는다. 이미 숨긴 탭은 반복 이관하지 않는다.
아카이브 실패 시 원본을 숨기지 않고 실패 사실을 알린다.
보이는 날짜 탭은 오늘 것 하나만, 월간·출력·이력 등 업무 탭은 표시 유지.
후속 완료가 확인된 과거 같은 월간/일회성 업무는 '미완료 → [날짜] 처리 완료'처럼 이력을 남긴다.
매일 반복되는 업무는 다음날 완료했다고 전날까지 완료로 바꾸지 않는다.
DESK 자료는 Blair 또는 Aria,Blair 공동 담당만 개인 업무 이관. Aria 단독·담당 빈칸은 제외.
DESK 원문은 별도 보존하고 당시 상태와 후속 완료 상태를 구분한다.

## 11. 셔틀상·Science·블로그·월말
셔틀상은 조사 → 간식·이름표 → 분배 → 사진·밴드 업로드의 별도 완료 상태다.
등원 요일이 달라 일부만 전달했으면 학생별 완료/남은 전달일을 분리한다. 분배 완료가 사진·업로드 완료를 뜻하지 않는다.
배송 대기·수령·제작·배부를 구분하며 택배 도착은 확인된 경우만 기록한다.
12월 Science/Craft 준비는 별도 담당자가 진행해 이번 준비 업무가 수행 불필요라는 확정 예외가 있다. 재개 지시 전 다시 투두로 올리지 않는다.
이 예외는 특정 날짜 Science 수업 지원·사진/영상 촬영 업무와 별개다.
블로그는 학사일정 이미지·원고·말일 예약발행을 구분하고 실제 공휴일·확정 일정으로 작성한다. 미정 이벤트 내용을 지어내지 않는다.
월간 투두는 그달 원본을 만들고, 미래 월 행을 임의로 선생성하지 않는다.
월말 프린트 전환은 기존 사용월 상태를 아카이브한 뒤 다음 준비월/사용월을 정확히 연결한다. 새 반·자료·부수는 최신 확정표로 다시 읽는다.
미완료 활성 이월·미래 확정 준비 예약·사용자 지정 예외가 월말 전환에서 사라지지 않도록 연결한다.

## 12. 대기명단 웹사이트와 이 문서의 경계
이 저장소의 대기명단 사이트와 업무표 운영은 별도다. 문서 변경을 위해 사이트 코드·서버·데이터를 수정하지 않는다.
웹사이트의 실제 등록 신청이 교재 청구·이름표 제작 완료를 의미하지 않는다. 등록 확정 정보를 별도로 확인한다.
무료 서버 일시 중지 등 장애는 현재 상태·원인 확인 후 별도 요청 범위에서 처리한다. 이 문서에 접속키·학생 데이터는 넣지 않는다.

## 13. 실무 전 확인 순서
1. 최신 사용자 변경과 이 문서를 읽는다.
2. 해당 사용월 원본·확정 명단·기존 출력/청구/완료 상태를 읽는다.
3. 해야 할 일과 이미 처리한 일, 부분 완료, 수행 불필요를 구분한다.
4. 학생·업무 식별을 대조하고 부족분/누락분만 반영한다.
5. 실제 처리 결과를 원본·일간·학생별 표·이력에 일관되게 기록한다.
6. 재조회해 체크·문구·수식·링크·표시 잘림을 확인하고 결과를 짧게 전달한다.
